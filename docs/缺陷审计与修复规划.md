# Arboris-Novel 缺陷审计与修复规划（统筹 Go Gateway 架构）

> 当前状态提示（2026-06-02）：本文是 2026-03 审计规划，不代表当前运行代码。当前索引中没有 `backend/app/tasks/chapter_tasks.py`；章节异步生成以 Go Gateway task dispatcher + Python `task_worker.py` 为准。涉及旧 Celery 章节任务和旧 Gateway 设计的修复项需按当前代码重新复核。

> 日期：2026-03-17

## 1. 背景

基于 OWASP LLM Top 10 (2025)、FastAPI 生产部署最佳实践、同类 AI 写作平台架构对标，对项目进行全面审计。

项目已实现双层架构：**Nginx → Go Gateway (3000) → FastAPI (8000)**。Go Gateway 已完成 JWT 认证、Redis 限流、WebSocket Hub、Task Dispatcher、反向代理。但 Python 端仍保留了大量被 Go 层取代的冗余实现，且两层之间存在配置不一致和安全盲区。

## 3. 修复清单（14 项，4 个优先级）

### P0 — 安全漏洞（5 项，部署前必修）

#### #1 OAuth 回调 XSS 注入
- **文件**: `backend/app/api/routers/auth.py:88-106`
- **问题**: `register_with_linuxdo` 将 `token_json`（来自外部 OAuth 回调）直接拼入 `<script>` 标签，未转义。若 token 中含 `</script><script>alert(1)` 即构成存储型 XSS。
- **修复**: 用 `html.escape()` 转义 `token_json`，或改为后端重定向 + URL fragment 传递 token。

#### #2 CORS 配置化（Go + Python 双层）
- **Go 端**: `gateway/internal/middleware/middleware.go:67` 硬编码 `Access-Control-Allow-Origin: *`
  - 修复: `gateway/internal/config/config.go` 新增 `CORSConfig` struct（`allow_origins`, `allow_credentials`）
  - `middleware.go` 从配置读取，生产环境限制为实际域名
  - `gateway/config.yaml` 新增 `cors` 段
- **Python 端**: `backend/app/main.py` 保留可配置 CORS 作为深度防御
  - `config.py` 新增 `cors_origins: str` 字段（逗号分隔列表），默认 `"http://localhost:5173"`
  - `main.py` 读取 `settings.cors_origins_list` 替换硬编码 `["*"]`

#### #3 WebSocket 认证统一到 Go 层
- **文件**: `backend/app/api/routers/writer_progress.py:19-24`
- **问题**: Python WebSocket 端点自己解析 JWT，绕过 Go Gateway 认证链。任何人可订阅任意项目的生成进度。
- **修复**: Go Gateway 的 `/api/*` 代理已注入 `X-User-ID` header；Python WebSocket 端点改为从 header 读取 `user_id` 并校验 project 归属，移除自行 JWT 解析逻辑。

#### #4 默认管理员密码必填化
- **文件**: `backend/app/core/config.py:72`
- **问题**: `admin_default_password` 默认值 `"ChangeMe123!"` 硬编码。`init_db.py` 每次启动自动创建管理员。忘设环境变量 = 公开后门。
- **修复**: 去掉默认值 → `Field(..., env="ADMIN_DEFAULT_PASSWORD")`，未配置时 Pydantic 校验报错、应用无法启动。

#### #5 数据库密码日志泄露
- **文件**: `backend/app/core/config.py` `sqlalchemy_database_uri` 属性
- **问题**: `URL.render_as_string(hide_password=False)` 将密码明文写入连接串。配合 `session.py` 的 `echo=settings.debug`，开发环境下密码直接打到 SQLAlchemy 日志。
- **修复**: 改为 `hide_password=True`。

### P1 — 生产稳定性（3 项）

#### #6 删除 Python 限流中间件（已被 Go 取代）
- **文件**: `backend/app/core/rate_limit_middleware.py` + `backend/app/main.py`
- **问题**:
  1. Go Gateway 已有 Redis 分布式限流（RPM/RPS/TPM/并发槽），覆盖所有 `/api/*` 流量
  2. Python `RateLimitMiddleware` 依赖 `request.state.user_id`，但中间件先于路由 `Depends` 执行，`user_id` 永远为 `None` → 所有请求直接放行
  3. `self.user_requests` 是 `defaultdict`，永不清理 → 内存泄漏
- **修复**: 从 `main.py` 移除 `RateLimitMiddleware` 注册。删除 `rate_limit_middleware.py` 文件。

#### #7 Celery DatabaseTask 会话泄漏
- **文件**: `backend/app/tasks/chapter_tasks.py:29-43`
- **问题**: `_session` 是类属性（非实例属性）。Celery worker 复用 Task 实例时 session 共享。异常退出未 `close_session()` → 连接泄漏、事务脏读、`"MySQL server has gone away"`。
- **修复**: 改为 `async with AsyncSessionLocal() as session:` 上下文管理器，确保任务级 session 隔离。

#### #8 JWT 过期时间过长
- **文件**: `backend/app/core/config.py:37-41`
- **问题**: `access_token_expire_minutes` 默认 `60*24*7 = 10080 分钟（7天）`。行业最佳实践 15-60 分钟。无 refresh token 机制，token 一旦泄露攻击窗口长达一周。
- **修复**: 缩短至 `60*24 = 1440 分钟（1天）` 作为折中（纯前端 SPA 场景），并在 `env.example` 中标注。后续可实现 refresh token。

### P2 — 架构缺陷（3 项）

#### #9 后台任务异常被静默吞掉
- **文件**: `backend/app/api/routers/writer.py:244-252` 等多处
- **问题**: `asyncio.create_task(...)` 创建的后台任务若抛异常，无 callback 捕获，异常被 asyncio 事件循环吞掉。向量入库、摘要生成等关键后处理可能无声失败，用户毫不知情。
- **修复**: 使用已有的 `backend/app/core/safe_task.py`（若已实现）或新建 `safe_create_task(coro, name)` 工具函数（内含 `try/except + logger.exception()`），替换所有裸 `asyncio.create_task` 调用。

#### #10 LLM 客户端缓存无大小限制
- **文件**: `backend/app/services/llm_service.py:34`
- **问题**:
  1. `_CLIENT_CACHE: Dict[str, Any] = {}` 无上限、无过期，理论上可无限增长
  2. `cache_key` 包含 API key 前 8 位，属于内存中的敏感信息残留
- **修复**: 改用 `cachetools.LRUCache(maxsize=32)` 替换；`cache_key` 改用 `hashlib.sha256(api_key.encode()).hexdigest()[:16]`。

#### #11 Go Gateway JWT Secret 硬编码
- **文件**: `gateway/config.yaml` — `jwt.secret: "your-secret-key-change-in-production"`
- **问题**: 默认值不安全，忘改就是公开后门
- **修复**: `config.go` 的 `Load()` 中添加 `viper.AutomaticEnv()` + `viper.SetEnvPrefix("GATEWAY")` 支持环境变量覆盖；启动时校验 secret 非默认值。

### P3 — 可观测性 & 健壮性（3 项）

#### #12 健康检查不检查依赖（Python 端）
- **文件**: `backend/app/main.py` `/health` 端点
- **问题**: 静态 JSON `{"status": "ok"}`。数据库挂了、Redis 挂了、Qdrant 挂了，健康检查仍返回 200。Docker/K8s 无法自动重启故障实例。
- **修复**: 添加 DB ping（`SELECT 1`）。Redis/Qdrant 可选检查。任一核心依赖失败返回 503。

#### #13 日志无 request_id 关联
- **问题**: 并发场景下多个章节生成的日志交织，无法区分属于哪个请求。debug 时只能靠时间戳猜测。
- **修复**: 使用已有的 `backend/app/core/request_id_middleware.py`（若已实现）或新建中间件，生成 `request_id`（UUID4），通过 `contextvars` 注入 logging context。Go Gateway 已有 request logger 可关联。

#### #14 Go Gateway CORS 缺少 `Access-Control-Allow-Credentials`
- **文件**: `gateway/internal/middleware/middleware.go:67-70`
- **问题**: 当前 CORS 设置缺少 `Access-Control-Allow-Credentials: true`。前端通过 Cookie 或 Authorization header 发送跨域请求时会被浏览器拦截。
- **修复**: 在 #2 CORS 配置化后，按配置添加 `Allow-Credentials` header。
