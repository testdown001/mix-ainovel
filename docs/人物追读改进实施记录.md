# 人物追读改进实施记录

日期：2026-10-13。源码范围：`remote-src/backend`、`remote-src/frontend`。

## 本次已实现

1. **人物依据贯穿规划。** 初始章纲、续纲、重排、蓝图审稿、完整/轻量导演与逐场生成共享有长度预算的人物上下文，直接携带人物欲望、缺陷、性格、关键关系、情感核心和读者承诺。逐场正文的人物卡独立于背景截断保留。
2. **新增可选的章级人物与阅读期待卡。** `character_focus` 含重点人物、当下目标、得失意义、行动或选择、代价、关系变化、后续期待。新章纲可生成，写作台可编辑；允许空值、旧章纲和安静章节，不要求每章强行牺牲或反转。
3. **修复规划落库与读取。** 统一 `metadata.planning`，兼容历史顶层字段，并同步章节蓝图中的执行约束。预测等其他 metadata 保留；旧表记录不会覆盖章纲中的当前选择；清空人物卡或禁写项也能正确生效。
4. **人物修改使预生成导演失效。** 缓存指纹加入章级规划和人物上下文，人物动机、关系或选择变化后不再复用旧导演。
5. **审稿检查人物牵挂。** 蓝图评分新增 `character_attachment`，要求定位具体人物、章节、选择和关系后果；兼容旧七维报告。人物维度存在可定位严重问题时，即使总分较高，也可在既有一轮预算内定向修订。
6. **清理冲突的节奏规则。** 移除批次末必须新增危机/悬念、固定 30%/40%/30% 爽点比例；保留全书长线目标，并允许局部兑现、日常、关系推进与余波。
7. **质量展示使用实际评审。** 缺少评审时显示“尚未评估”，不再用字数和完成率制造人物、张力等质量分。已有 AI 试读反馈可在情感审校面板查看，只有正文 SHA-256 与报告一致、报告状态可用时才展示结论；明确标为模拟意见。

## 验证

- 后端覆盖规划清洗与迁移、真实数据库落库到导演读取、旧表兼容、保留场景约束和状态、修改后的缓存失效、完整/轻量导演输入、场景背景截断、两条章纲入口、蓝图审稿、传统与 Agent 主链、fast/standard/literary 分支及提示词同步。
- 主要集成批次 102 项通过；扩展批次中一条旧的强制批次悬念断言已按新行为更新，相关 35 项回归全部通过。后台章纲与规划回归 18 项通过，提示词同步回归 5 项通过。
- 前端全量 108 项单测通过，新增的人物维度中文标签用例及对应测试文件 5 项通过；Vue/TypeScript 类型检查与生产构建通过。
- `git diff --check` 通过。构建仍有既有的 Browserslist 数据陈旧和大 chunk 提示。

测试使用模拟模型响应和内存数据库，没有调用真实付费模型。上述结果验证数据流与行为契约，不代表已经证明真人追读率提升。

## 生效方式与后续范围

本次为本地源码改进，尚未部署。使用更新的前端构建并重启后端后，新生成/重排章纲可使用新字段；旧章纲也可在写作台手动补充。无需新增数据库列或批量覆盖已有正文。

默认提示词遵循现有启动同步机制；管理员在数据库中自定义过的提示词会保留，需要核对并合并本次人物规划与审稿规则。没有强行覆盖自定义模板或改变档位、积分与生成模式开关。

本次完成的是规划到生成的基础贯通。分析中独立的“人物场景试读入口”、剧情选择不足时的专门场景重规划流程，以及让所有模式默认抽取人物意义记忆，仍属于后续功能范围。现有口吻试写、人物意义记忆和连续章节盲读能力保留。

下一步效果验收应使用同一立项、共同前情和相近模型预算，盲读新旧链路的 3–5 个连续章节，记录在乎谁、原文依据、关系变化是否被延续，以及是否愿意继续阅读。
