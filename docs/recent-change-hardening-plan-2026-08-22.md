# 近期改动发布加固实施方案（2026-08-22）

## 1. 背景与目标

近期提交已经把产品从单纯的 AI 生成工具推进为长篇小说创作副驾，并在当前工作区继续落地了 M0～M3、小说详情页、灵感页和 AI 封面。审查同时发现：版本控制、数据库迁移、已定稿正文保护、图片成本、离线草稿以及历史容量治理仍存在发布风险。

本轮目标不是继续增加新功能，而是把现有成果收口到“可迁移、可回退、不会丢稿、成本可控、容量可观测”的发布基线。

## 2. 范围与非目标

### 本轮范围

1. 修复 Docker 部署使用旧镜像执行迁移的问题。
2. 确保 Legacy 数据库在 `stamp head` 前已满足当前 ORM 结构契约。
3. 重起草只新增待选候选，不取消作者已经确认的当前正文。
4. AI 封面增加档位、积分、并发互斥、失败退款和删除清理。
5. IndexedDB 草稿写入等待事务真正提交，并显式处理后台写入失败。
6. 版本历史采用游标分页，并暴露版本数量和正文存储字节数。
7. 增加覆盖上述契约的后端与前端回归。

### 非目标

- 不在本轮启动 M4/M5 新能力。
- 不删除任何现有章节历史或作者正文。
- 不自动清理既有孤儿封面；只保证此后删除作品会同步清理。
- 不在本轮拆分全部千行级路由和 Vue 页面；仅记录为后续重构任务。

## 3. 实施项与验收标准

### H1 数据库与部署链（P0）

- 部署顺序调整为：构建新镜像 → 启动新容器并执行启动修复 → 使用新容器执行 Alembic → 校验结构。
- `init_db` 补齐 M3 章节版本字段与索引，作为 Legacy 纳管前的安全网。
- Legacy 数据库执行 `stamp head` 前先比对 ORM 表/列；存在漂移时拒绝盖章。
- 验收：空库、Legacy 库和已纳管库均能到达唯一 Alembic head，且 ORM 无缺表缺列。

### H2 作者正文主导权（P0）

- 重起草成功后保留 `selected_version_id`、当前正文哈希和当前摘要。
- 新候选以最新生成批次进入待选状态；作者明确选版后才切换当前正文并推进修订号。
- 导出在候选待选期间仍包含原已确认正文。
- 验收：生成失败、生成成功未选版、选择新版三条路径都不丢失原正文。

### H3 AI 封面成本与文件生命周期（P1）

- 新增 `cover_generation` 能力位，默认创作者档及以上。
- 新增可配置积分价格 `credits.price.cover_generation`，默认 10 积分。
- 每次请求使用幂等流水号先扣费；失败自动退款。
- 同一用户同一时间只允许一个封面生成任务，避免跨作品并发超扣积分；同一作品自然也被互斥。
- 删除作品后 best-effort 删除持久化封面；重新生成仍原子覆盖同一路径。
- 验收：越权、余额不足、并发、失败退款、生成成功和删除清理都有测试。

### H4 本地草稿可靠性（P1）

- IndexedDB 写请求只有在事务 `complete` 后才视为成功。
- 防抖后台写入不产生未处理 Promise rejection，错误进入可见状态。
- 离页仍是 best-effort；产品文案不承诺浏览器无法保证的同步持久化。
- 验收：事务完成、事务中止和后台写失败均有单测或静态契约测试。

### H5 历史容量治理（P1）

- 历史列表默认每页 30 条，使用 `before_id` 游标加载更早版本。
- 响应返回 `total_count`、`total_content_bytes`、`has_more` 和 `next_before_id`。
- 不改变不可变版本语义，不自动删除候选或历史。
- 验收：历史超过一页仍可完整加载，列表不携带正文，容量统计准确。

## 4. 发布与提交拆分

当前仓库处于 detached HEAD，执行提交前必须先创建正式分支。建议拆分为：

1. `docs: add recent change hardening plan`
2. `fix(deploy): harden migration ordering and legacy adoption`
3. `fix(writer): preserve confirmed chapter during redraft`
4. `feat(cover): add billing concurrency and lifecycle guards`
5. `fix(editor): wait for indexeddb transaction completion`
6. `feat(history): paginate revisions and expose storage stats`
7. `test: cover release hardening contracts`

## 5. 发布门禁

- 后端相关回归全部通过。
- 前端类型检查与生产构建通过。
- `git diff --check` 通过。
- Alembic 单 head，空 SQLite 迁移演练通过。
- 生产 MySQL 数据副本完成备份、迁移、结构校验和回滚演练后方可部署。
