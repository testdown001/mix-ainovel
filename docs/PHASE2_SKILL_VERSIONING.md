# 第二阶段：写作技能版本化

## 目标

把写作技能从静态的运行时模块升级为可审计的技能卡：每次生成固定一个已发布版本，作者可以看到使用效果，管理员可以审核草稿、发布或回滚。

## 已落地范围

- `writing_skills`：技能卡元数据、作用域和执行模式（转换型 / 生成约束型）。
- `writing_skill_versions`：不可变的规则快照，状态为 `draft`、`published` 或 `retired`。
- `writing_skill_usages`：生成或手动应用的使用回执，记录版本、章节、是否改变内容和作者接受反馈。
- 生成解析器只解析当前已发布版本，并将快照写入 ContextPlan；草稿不会进入 Prompt。
- 发布旧版本会退役当前版本；回滚是复制目标版本并发布新版本，保留完整历史。
- 管理后台新增“写作技能”页，可查看版本审计、创建改进草稿、人工发布和回滚，并展示使用次数与接受率。

## 首批内置技能

1. **有限视角控制**：限制信息范围，避免上帝视角和作者替读者解释真相。
2. **少修辞与克制表达**：抑制形容词堆叠、密集比喻和抽象抒情，优先行动与可验证细节。
3. **自然收束**：用人物动作、对白或具体信息结束章节，避免隐喻式升华和命运旁白。

原有六个转换型技能也已建立初始版本卡，保持既有手动润色能力兼容。

## 安全边界

技能版本只允许保存声明式规则、提示和检查器键，不执行数据库中的 Python、Shell 或任意代码。AI 改进接口的语义是“创建草稿”，发布始终需要人工操作。

## 后续迭代

- 将质量评分结果回写到使用回执，形成版本级 A/B 指标。
- 为作者提供项目级技能副本和差异编辑器。
- 将 `checker_keys` 接入跨章节诊断器，输出规则命中证据。
