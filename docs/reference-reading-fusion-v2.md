# 参考小说的阅读动力与多书融合

这次改动把参考资料从“书名、梗概和文风形容词”，扩展为贯穿灵感、蓝图、排章与正文的阅读动力方案。

## 行为变化

- 手输书名会解析到参考库并保存到项目，最多三本，按用户输入顺序绑定。尚未分析的书也会保留绑定及状态。
- 已完成的库分析始终进入灵感对话；客户端传入的搜索摘要作为补充，不能屏蔽库里的记忆卡和桥段分析。前端跳过已就绪书目的重复检索。
- 单本也提炼人物牵挂、期待、进展、兑现与余波。多本要求每本明确贡献、转换方式与依据，再决定统一声音和冲突取舍。
- 融合使用结构化校验，缺书、虚构来源或生成失败时返回有明确标记的临时方案，不宣称完整融合已完成。
- 融合检查完整绑定集合、绑定顺序和资料指纹。后台每次轮询重新开事务；模型返回后重新核验绑定与资料，避免覆盖重新绑定的结果。
- 老项目、慢分析或后台进程中断后，在实际构思、蓝图或章节读取时补齐融合。正常章节复用已有方案；临时方案也缓存，避免每章反复请求模型。重新绑定可重试融合失败。
- 蓝图设定与章纲使用同一方案；普通生成和逐场景生成均携带有界的参考指导。逐场景模式把它放在前情压缩之外，并补充本章选中的参考桥段。

## 创作原则

几本参考各贡献合适的阅读机制，不能每本各占几章、轮换文风，或把不同视角和句式配额同时塞给模型。本书已确认的设定、人物声线和章纲优先。

阅读动力以人物的目标、代价、选择和关系变化为依据。蓄势要有进展，兑现要改变处境，并给情绪留下余波；日常、低谷、关系与收束章可以承担其中一环，不要求每场都走完一个抑扬循环。

检索与书评分析并不等于阅读完整原著。AI 仿写不会被用作融合分析的原文证据，资料不足会明确标记。

## 验证与上线范围

回归覆盖书名持久化、完整集合与顺序、慢分析、生成期间重新绑定/重新分析、旧方案升级与缓存、结构化失败降级、库资料与搜索摘要并存，以及长前情下逐场景保留参考指导。前端验证包含类型检查、参考选择测试和生产构建。

本批无需数据库迁移：新字段保存在既有 JSON 列中。参考提示词在正常启动同步时更新；管理员自行接管的提示词仍按项目原有规则保留。

这些检查证明了传递与融合机制的行为，没有代替真实模型的连续章节质量评测。判断是否更有追读感，应以相同立项、模型和字数预算生成连续章节，盲评人物牵挂、期待兑现、情绪余波与统一声音。
