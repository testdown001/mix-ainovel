# ADR-001：章节修订的分层不可变存储

- 状态：已接受
- 日期：2026-08-21
- 对应路线图：M0、M2、M3、M4

## 背景

长篇作者首先需要确信正文不会丢失，也需要能说明任意文本为什么发生了变化。将每次键入都写入数据库会造成大量无意义记录；直接覆盖当前版本又会破坏恢复、Diff、AI 采纳和诊断证据链。

## 决策

章节内容采用两层存储：

1. **本地草稿层**：浏览器 IndexedDB 保存防抖草稿，仅用于断网保护和恢复提示，不作为历史版本。
2. **服务端修订层**：显式保存、AI 采纳、整章定稿、恢复历史和离页保护等关键节点创建不可变版本；已有版本只读。

恢复旧版本必须创建一个以旧版本为父节点的新版本。每个版本至少记录：来源、父版本、内容哈希、创建时间、操作者和变更说明。

## 后果

- 编辑接口不得再原地修改已选中的 `ChapterVersion.content`。
- AI 建议必须绑定源版本和文本范围；源版本不一致时必须提示重新生成。
- 数据库中只保留关键快照，草稿高频写入不会造成版本表膨胀。

## 迁移要求

现有手写版本和生成版本先保留。实现新写入路径时，为历史记录补齐可推导的来源标签；无法可靠推导的记录标为 `legacy`。
