# 管理后台小说删除

管理后台仅允许删除明确标记为 `system` 或 `ai_test` 的项目。普通用户创建、导入，以及用户使用 AI 创作的小说，来源均为 `user`，在后台受保护。未知来源也受保护。

来源字段 `novel_projects.creation_source` 默认值为 `user`，旧数据迁移也默认保护。不得通过标题、是否调用 AI、管理员归属等启发式规则直接授予删除权限。普通创建 API 不接收来源设置；可信内部创建路径可向 `NovelService.create_project` 传入 `ProjectSource`。NovelBench 播种自动使用 `ai_test`。已有项目只有在核实来源后，按具体编号进行一次性标记。

删除流程：

1. 首个弹窗显示标题和完整编号，输入准确的“删除”后，调用 `POST /api/admin/novel-projects/{id}/deletion-confirmation`。
2. 后端验证管理员权限和项目来源，签发有效期 5 分钟的确认凭证；此时不删除数据。
3. 第二个独立弹窗清空输入，要求再次输入“删除”，提交 `DELETE /api/admin/novel-projects/{id}`，携带第二次确认文本及凭证。
4. 后端再次校验权限、来源、归属、凭证签名与期限。凭证绑定管理员、项目和来源，使用独立于登录令牌的签名域。
5. 复用项目删除事务及关联数据级联，提交后清理封面、缓存和章节向量。取消或失败后清空两次输入和凭证。

相关回归覆盖用户 AI 作品保护、未知来源保护、权限、两次输入、凭证伪造/过期/跨项目/跨管理员、确认期间来源变更、关联数据级联及迁移幂等性。发布与来源标记不执行项目删除；管理员仍需在页面完成双重确认。

批量删除支持桌面表格与移动列表勾选、全选可删除项目和清空选择，每批最多 100 项。用户作品与未知来源不能勾选。两个弹窗均显示本批标题和编号，打开确认后锁定勾选范围。

批量接口为 `POST /api/admin/novel-projects/deletion-confirmation` 和 `DELETE /api/admin/novel-projects`，请求携带 `project_ids`。短时凭证绑定整批项目、来源、归属和管理员；编号顺序调整不改变范围，增删项目或变更归属均需重新确认。所有项目在同一个事务中删除；包含受保护项目、缺失项目或数据库失败时整批拒绝/回滚，提交后才清理文件、缓存和向量。
