# 蓝图模式优化：竞品与研究对照（2026-10-23）

- 代码基线：`65d03c8`
- 范围：只看「立项书 → 蓝图设定段 → 章纲段 → 审稿门 → 续排」这一段。正文链路、检索、记忆见 `novel-creation-workflow-analysis-2026-10-17.md`，本文不重复。
- 竞品资料的标注：**[V]** 表示打开过官方文档、changelog 或论文原文；**[3P]** 表示只有第三方测评。阅文、番茄、起点在规划功能上几乎没有 2025–26 年的公开文档，国内资料最详细的是开源项目 InkOS。

## 一、现状速写（以代码为准）

| 环节 | 现在怎么做 | 依据 |
| --- | --- | --- |
| 设定段 | 一次产出书名、卖点、梗概、世界观、金手指、人物、关系、分卷、伏笔 | `prompts/screenwriting.md` |
| 分卷 | 每卷只有 `name / start_chapter / end_chapter / arc_goal / climax_hint` 五个字段 | 同上，输出 schema |
| 人物 / 金手指 | 都是**静态快照**：人物 6 个文本字段；金手指成长只有一句 `growth_potential` | 同上 |
| 章纲段 | 默认一次承诺 50 章，每 25 章一批，每章带 5 个规划字段（creator 档及以上） | `blueprint_generation_service.py:54-57` |
| 节奏 | 用通用章号锚点兜底：1-3 章开局，5-8 章首个爽点，10-12 章，20-30 章，40-50 章 | `prompts/screenwriting_outline.md` |
| 题材 | `genre_profile_service` 内置题材配置（钩子、爽点、节奏），**只在正文生成时使用**，蓝图阶段读不到 | 只被 single_version / scene / prompt_context 三个模块引用 |
| 审稿 | 八维商业量表，低分时按块或按章号区间修订一轮再复审 | `blueprint_review_service.py`、`prompts/blueprint_review.md` |
| 重生成 | 只能整本蓝图覆盖重来，一旦有章节就返回 409；章纲可以单章重生成，或批量重生成未完成的章 | `BlueprintDisplay.vue`、`ChapterOutlineSection.vue` |
| 漂移处理 | `outline_revision_service` 在某章定稿后，对比后续 K 章大纲并写入 `revision_hint`。**只是提示，不改大纲**，仅 premium 档；**本章**的章纲不会按实际正文更新 | `outline_revision_service.py` 文件头 |

结论：质量门（推演、审稿、定向修订）已经比市面产品重；短板在**结构的粒度和时间性**，以及**作者对局部的掌控**。

## 二、竞品与研究里值得借鉴的做法

- **Novelcrafter Progressions** [V]：设定条目可以挂「从某个场景起生效」的补充或替换。AI 写到那个位置之前看不到，回头改前面的章节时也不会读到未来状态。另有 Matrix 视图（条目 × 场景），用来追踪支线和人物分布。
  - https://www.novelcrafter.com/docs/codex/additions/
  - https://www.novelcrafter.com/help/docs/plan/plan-views
- **Sudowrite** [V]：
  - 大纲支持单章重写和拖拽，有历史恢复。
  - Draft 会显示本次用了哪些设定卡，单条可以对 AI 隐藏。
  - 正文写偏后，用 **Update** 把章摘要改成和正文一致，即正文反向同步回大纲。
  - Canvas 白板内置英雄之旅、言情等结构模板。
  - https://docs.sudowrite.com/using-sudowrite/1ow1qkGqof9rtcyGnrWUBS/outline/3owKyHXUm1bCdp41b2Npjk
  - https://feedback.sudowrite.com/changelog/mag-story-bible-detection-and-visibility-update
- **InkOS**（开源，v1.6.3，2026-07）[V]：
  - Architect 先产出故事框架、卷图、人物卡和全书长期方向（`author_intent.md`）。
  - 章级意图边写边生成，另外维护一份「接下来 1–3 章重点」（`current_focus.md`）。
  - 权威状态存 JSON，再生成 Markdown 给人看；资源（灵石、法宝等）单独记账。
  - 审计把「偏离大纲」列为一个维度。
  - https://github.com/Narcooo/inkos
- **蛙蛙写作、灵犀速写** [3P]：按题材预置工作流（例如都市异能：书名 → 人设 → 世界观 → 卷纲）；有按题材分的「黄金三章」模板（战神、甜宠、赘婿等）；可以开分步确认。
  - https://www.qbitai.com/2024/08/180494.html
  - https://post.smzdm.com/p/al359e40
- **笔灵** [3P]：大纲附「编辑视角」的审稿亮点，作者先确认大纲再逐章写。
- **StoryWriter**（arXiv 2506.16445）[V]：先生成事件并逐个校验一致性，再把事件分配到各章、穿插排布，而不是直接让模型逐章写摘要。
- **DOME**（NAACL 2025）[V]：动态分层大纲，随已写内容调整。
- **Xie & Riedl**（EACL 2024）[V]：悬念规划循环，交替生成「主角行动」和「阻碍」，每轮让成功更难。
- **WebNovelBench**（EACL 2026 Findings）[V]：用 4000 多部中文网文做基准，评分换算成在人类作品中的百分位。
- **平台环境** [V]：起点 2025-04 发声明反对用 AI 替代核心创作，2025-08 对 AI 痕迹重的作品撤榜、撤推荐。差异化应该放在「作者主导、AI 辅助规划」，不要做一键全书。https://news.ifeng.com/c/8w7TegRtCxi

## 三、改进建议（按影响排序）

### P0-1　卷纲做厚，章纲做薄（前粗后细）
- 卷卡结构化。新增字段：本卷地图/舞台、主要对手、主角境界或资源区间（起→止）、新登场人物、核心爽点类型、人物弧阶段、卷末钩子。
- 设定段对**全书**每一卷都产出卷卡，章纲段默认只细化**前 10–15 章**（黄金三章加第一个小高潮）。之后的章纲走现有的续排和滚动审稿门，并新增一份类似 InkOS `current_focus.md` 的「近期焦点」（接下来 1–3 章重点），续排和任务书都读它。
- 收益：首次蓝图的 token 和等待时间大约减半；50 章细纲在第 15 章之后基本都要被漂移推翻，现在等于白付钱。卷卡还能给 `volume_retrospective` 和续排一个可以对照的目标。
- 实现落点：
  - `_sanitize_volumes`，以及 `screenwriting.md` 里的 volumes schema；
  - `OUTLINE_PROMISED_DEFAULT`，改成可配置，放进 SystemConfig `blueprint.initial_outline_chapters`；
  - `NovelBlueprint` 的 volumes JSON 只是加字段，不需要迁移。

### P0-2　人物和金手指带「章节生效区间」（借鉴 Progressions）
- 人物、金手指、势力增加 `stages: [{from_chapter, state, trigger}]`。例如「第 30 章筑基」「第 80 章身份暴露」。
- 生成第 N 章时只注入 `from_chapter ≤ N` 的那些阶段。这和 3c27416 已经做的「revision-safe」as-of 语义是同一条线，把它延伸到蓝图静态设定上，防止提前剧透境界或身份。
- 金手指的 `growth_potential` 由一句话改为分阶段的列表，压力推演中「金手指崩坏失速章预测」的结果可以直接落成阶段节点。

### P0-3　题材 profile 前移到蓝图阶段
- 蓝图阶段改为读取 `genre_profile_service`：章纲 prompt 里那组固定节奏锚点，换成按题材取的锚点（悬疑、言情、升级流的节奏本来就不同，正文侧已经这样做了，蓝图侧反而是一刀切）。
- 增加一套按题材分的「黄金三章」模板，作为前 3 章章纲的生成骨架；同一套模板也作为审稿量表 `opening_strength` 和 `first_coolpoint_timing` 的题材基准。
- 成本低，见效快。只改代码常量和 prompt，不改 schema。

### P1-4　正文回写章纲，漂移提示交给作者处理
- 选定版本后，后台把**本章**章纲的 `summary` 和 planning 改成实际写出来的内容；原计划存为 `metadata.planned_snapshot`，便于对照，采用 Sudowrite Update 的思路。这样后续续排、滚动审稿、mission 预生成读到的都是事实，而不是旧计划。
- `revision_hint` 目前只注入 prompt，前端看不到。在 `ChapterOutlineSection` 上展示，提供「采纳 / 忽略」两个按钮。当前的设计原则就是「建议给作者，作者终审」，只是还没有做界面。
- 漂移检查本身成本很低，可以考虑从 premium 放宽到 creator 档（需评估成本）。

### P1-5　局部重生成和备选方案
- 把审稿门已有的 `settings:<块名>` 定向修订能力开放给作者：「只重写金手指」「只重写第 2 卷」「只重写某个配角」。有章节之后也能用，不受 409 限制，因为只动未落笔的部分。
- 关键节点出 2–3 个备选供作者挑：开篇前 3 章、每卷的卷末高潮。这里花模型调用最划算，也最能体现作者主导。

### P1-6　章纲之前先做事件层（StoryWriter 思路）
- 卷内先生成 8–15 个「关键事件」（含因果前置和涉及人物），做一次一致性校验，再分配到章并穿插排布。
- 这样能直接压低「水章」和中段塌陷，也让 `chapter_function` 的分布有事件依据，而不是凭空分配标签。

### P1-7　人物和伏笔 × 章节矩阵视图
- 数据已经齐全：`chapter_blueprints`、伏笔账本、`foreshadowing_ops`。做一张只读矩阵：谁在哪些章出场，哪条伏笔埋在哪、兑现在哪、拖了多久。
- 现在作者要逐章点开才能看到这些，矩阵一眼就能看出「某配角消失 40 章」「核心伏笔无兑现章」。

### P2
- 8. 确认页增加「编辑视角亮点」（3–5 条卖点和风险），从现有审稿报告里提炼，不需要额外调用。
- 9. 审稿总分附「同题材百分位」：用题材内历史蓝图的分数分布换算，比绝对分更好解释，也不会误导「70 分及格」。
- 10. 蓝图设定注入透明化：生成正文时显示用了哪些设定卡，可以单条屏蔽。这个和 10-17 报告的「实际上下文视图」合并做。

### 不建议
- 一键全书 Agent，或以平台趋势扫描（InkOS Radar）作为默认步骤。前者与平台政策相抵触；后者数据来源有合规风险，最多作为压力推演的可选输入。
- 再堆一层审稿 Agent。现有质量门已经够重，瓶颈在结构粒度和作者掌控，不在评审次数。

## 四、建议的落地顺序

1. **P0-3 题材前移**：一个 PR，只改 prompt 和常量，可以马上验证效果。
2. **P0-1 卷卡加首批章数可配**：一个 PR，volumes 字段扩展、前端 `VolumesSection` 展示、审稿量表 `volume_escalation` 改为读卷卡。
3. **P1-4 正文回写加 hint 界面**：一个 PR，复用 `outline_revision_service` 和选版触发点。
4. **P0-2 生效区间**：需要和 as-of 读取链路一起设计，单独做设计评审。
5. 其余按需安排。

验收：沿用 10-17 报告第七节的连续阅读法。另外每项改动跑一次 `novel_bench_service` 回归，对比前 15 章的开篇强度、首个爽点章号，以及第 15–50 章的续排漂移提示数量。

## 五、二期重规划：从「大纲文档」到「可运行的故事引擎」

第三节是对标修补。这一节是另一种定位：蓝图不再是一份一次性生成的大纲文档，而是三样东西：

| 层 | 是什么 | 回答的问题 |
| --- | --- | --- |
| 契约 | 创作宣言 + 读者承诺账本 | 这本书答应读者什么、作者为什么写它 |
| 引擎 | 欲望、压力源、资源账、角色秘密、战力曲线、升级规则 | 下一章的处境从哪里来 |
| 时间线 | 人物、世界、承诺随章节变化的状态 | 写到第 N 章时世界是什么样 |

章纲变成从引擎**派生**出来的快照，随时可以重算；作者改的是引擎和契约，不是五十条摘要。

### 5.1 倒推规划：先写结局，再回填伏笔
现在的伏笔靠审稿门「伏笔落章率」事后检查。倒过来：设定段先定全书终局和每卷卷末高潮，然后让模型回答「要让这个高潮成立，前面必须发生什么」，逐级回填到章。伏笔是被需要才埋的，兑现从结构上保证，不再靠复查。改动集中在 `screenwriting.md` 的生成顺序和 `foreshadowings` 的来源，不动 schema。

### 5.2 角色自述：每个主要角色写一段独白
蓝图落库后，让每个主要角色用第一人称回答三件事：最怕什么、对主角隐瞒了什么、第一卷结束时会做出什么选择。答得平的人物当场暴露没有戏。产物存进人物卡：`secret` 成为引擎的伏笔来源，`voice_sample` 给后面的对白生成当声音基准。`concept_voice_service` 已有试写能力，可以复用。

### 5.3 投放级预览门：先证明能被点进来
在生成完整蓝图之前，只花一次调用生成三样决定点击率的东西：书名候选、平台风格的简介、第一章开头五百字。作者选定或改写后再出蓝图。这一步决定蓝图的基调，也是第一个作者参与点；立项书里的书名候选和声音试写可以合并进来。

### 5.4 跳读测试：只读钩子链和标题链
把章纲全部的章末钩子按顺序抽出来连成一段读；再把章节标题连成一列读。番茄读者就是这么扫书的。钩子链单独读不动人，章纲就是不合格，不管单章摘要写得多细。零模型成本，可以作为审稿门的输入，也可以直接给作者看。

### 5.5 试读间：几种读者人格的弃书点回放
压力推演现有的毒点清单是通用的。改成由三到四种读者人格（追更党、老白、女频读者、只看前三章的人）分别读前十章章纲，各自给出在第几章弃书、为什么。输出一条按章的预测留存曲线。注意这只是模型模拟，不能代替真实读者数据，但在蓝图阶段没有别的反馈来源。

### 5.6 战力曲线图：金手指的经济学
升级流的核心风险是碾压失速。把每卷主角能力、资源、对手强度列成数值表，画成两条曲线，碾压比超过阈值的区间直接标红。压力推演现在用文字预测失速章，改成数值后既可以画图，也可以作为续排时的硬约束。

### 5.7 活蓝图：带时间滑块的设定集
人物卡、世界状态、承诺账本随定稿章节自动更新为「截至第 N 章」的版本，界面上一个滑块回看任意章时的世界。数据大部分已有：`CharacterState`、`Timeline`、`world_state`、承诺台账。这是 P0-2「生效区间」的产品形态，也是作者回头修改前文时最需要的东西。

### 5.8 从一章长出一本书：另一个入口
不少作者是从一个场景开始的。入口双轨：除了现在的对话到立项书，允许作者直接用立项书写出第一章的三个版本，选定一个，再让蓝图从这一章「长」出来，保证蓝图和已经成立的声音、节奏一致。

### 5.9 创作宣言
蓝图顶部放一段作者自己写或从对话蒸馏的「我为什么写这本书，想让读者感受什么」，所有下游 prompt 以它为最高优先级意图。InkOS 的 `author_intent.md` 就是这个作用。成本几乎为零，但它是「作者主导」最直接的体现。

### 排序

| 闪光度 × 可落地 | 项 | 成本 |
| --- | --- | --- |
| 高 | 5.4 跳读测试、5.9 创作宣言、5.3 投放级预览门 | 低 |
| 高 | 5.1 倒推规划、5.2 角色自述 | 中，主要是 prompt |
| 高 | 5.7 活蓝图 | 高，依赖 P0-2 |
| 中 | 5.6 战力曲线、5.5 试读间 | 中 |
| 中 | 5.8 一章长出一本书 | 中，新增入口 |

建议先做 5.3 → 5.4 → 5.1 → 5.2 四项，它们串起来就是一条新的作者主流程：先被点进来，再定结局，再回填，再让角色开口。第三节的 P0 项可以并行推进。
