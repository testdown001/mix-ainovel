# 版本介绍 — 安全加固与性能优化（2026-06-11）

> 准确的提交历史请以仓库 `git log` 为准；本文按改动主题编写。

## 版本定位

本版本是一轮**安全与稳定性专项整改**，基于一次全面代码审查落地。核心目标：堵住未授权访问入口、修复生产网关的功能性故障、消除生成热路径的性能浪费。**建议尽快升级，并留意下方部署注意事项。**

## 主要变更

### 🔒 安全

- **收口 5 类未授权端点**：力量体系（世界观）、技能执行、写作模板、内部任务执行等端点补齐鉴权与归属校验，杜绝越权读写和匿名消耗算力
- **限流防绕过**：限流不再信任客户端可伪造的 `X-Forwarded-For` 首段，改用可信代理 IP；手机登录、验证码、密码重置等敏感端点纳入严格限流，封堵暴力破解
- **登录账号状态校验**：补齐 Linux.do OAuth 登录的账号封禁检查，与其他登录方式一致

### 🌐 网关（生产链路）

- **任务接口强制鉴权**：任务提交/查询/取消纳入 JWT 鉴权，用户身份一律以令牌为准，禁止伪造
- **JWT 契约对齐**：令牌补齐网关所需声明，修复此前网关侧鉴权链路无法正常工作的问题
- **稳定性修复**：消除 WebSocket Hub 的崩溃风险；打通实时进度推送链路；worker 由「一次抖动即永久下线」改为「冷却后自动恢复」

### ⚡ 性能

- **鉴权窄查询**：权限校验不再为此加载整本小说，消除枚举类请求的资源放大
- **LLM 配置缓存**：生成过程中的 LLM 通道配置读取加进程级缓存，单次生成减少数百次重复查库
- **消除缓存白写**：生成路径不再做「写入即作废」的全书缓存序列化，减少事件循环阻塞与 Redis 压力

### 💳 前端

- **订阅套餐动态化**：套餐 ID 与价格改为从后端实时拉取，消除硬编码导致的付错套餐/下单失败风险；异常时禁用购买并提示

## ⚠️ 部署 / 升级注意事项

1. **内部任务密钥（必须）**：内部任务执行端点现在强制校验 `X-Internal-Secret`，**未配置将拒绝服务（503）**。升级前请确保网关与后端配置了一致的内部回调密钥。
2. **JWT issuer / audience**：后端与 Go 网关的 `jwt.issuer` / `jwt.audience` 需保持一致（已提供默认值并向后兼容历史令牌）。
3. **反向代理需正确设置 `X-Real-IP`**：限流依赖可信代理传入的真实客户端 IP，请确认 nginx 等正确设置该头。
4. **LLM 配置生效有约 60 秒延迟**：后台修改 LLM 通道配置后，因新增缓存，最长 60 秒内生效（如需即时生效可调用预留的失效接口）。
